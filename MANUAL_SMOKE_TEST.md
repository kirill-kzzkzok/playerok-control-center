# Безопасный Telegram smoke-test после offline-исправлений

Этот документ — инструкция владельцу, не выполненный live-тест. Разработка не запускала рабочие workers и не меняла .env, рабочую SQLite, сессии или денежные разрешения.

## 1. Сначала только интерфейс

Остановить свой прежний экземпляр штатно. Сделать обычную закрытую резервную копию рабочей БД при остановленном приложении; не отправлять её в Git/чат. Новые миграции025/026 применяются штатным Store при запуске. Проверить наличие восстановления из резервной копии перед обновлением; миграция старых попыток консервативно помечает неопределённые операции и удерживает их резерв, не повторяет отправки.

Для отдельного ручного read-only запуска в PowerShell можно переопределить разрешения только в текущем процессе (рабочий .env останется прежним):

```powershell
$env:PLAYEROK_WRITES_ENABLED='false'
$env:PLAYEROK_AUTOMATION_ENABLED='false'
$env:TG_GIFT_PAYMENTS_ENABLED='false'
$env:TG_GIFT_REFUNDS_ENABLED='false'
$env:PLAYEROK_AUTO_ACCEPT_AGREEMENTS='false'
.\start.bat
```

Не менять действующий SOCKS/Worker/MTProto session ради этой проверки. Не запускать второй polling/сервис. Переменные PowerShell действуют на дочерний процесс; закрытие этого PowerShell уберёт временные переопределения. Перед любым последующим запуском проверить эффективные разрешения в панели, а не предполагать, что выключение сохранилось в .env.

1. `/start` → Товары → товар → Назад → Главная. Затем Заказы, Сообщения, Подарки, Ещё/Профиль/Настройки/Статистика. Должна оставаться одна текущая панель; квитанции и уведомления не исчезают.
2. Открыть локальный черновик, изменить безопасные поля, вернуться назад, перезапустить с теми же read-only разрешениями; открыть черновик снова. Не нажимать публикацию.
3. На настоящем ранее полученном уведомлении нажать «Ответить», ввести тестовый текст, проверить превью и нажать отмену. «Прочитано» — открыть подтверждение и отменить. **Не подтверждать отправку/mark_read в read-only smoke.** Это проверяет только UI, не настоящую запись API.
4. При «Экран устарел» открыть `/start`. При неизвестном исходе экрана — нажать «Восстановить меню» явно; это сбрасывает только навигационные подтверждения и не повторяет операции магазина. Старые кнопки commit/платежа не использовать.
5. Открыть Ещё → Инструменты → История/неопределённые операции и Результаты действий. До включения записей просмотреть ВСЕ PENDING/RETRYABLE_FAILED/PROCESSING/UNCERTAIN и ожидающие Gifts/цепочки/продвижение. Нельзя включать writes для интерфейсного теста, не разобрав накопленную очередь. Неизвестные исходы сверять по положительной серверной квитанции; отсутствие сообщения не доказывает неотправку.

При сетевом сбое не делать серию повторов. Проверить показанное состояние и /start. Не публиковать токены, cookies, session, access_hash, содержимое склада или полные логи с чужими данными.

## 2. Отдельная контролируемая выдача — только с новым явным разрешением

Заранее согласовать один реальный товар, один оплаченный заказ/получателя, цену/расход, нужные флаги и способ завершения. До этого пункта реальные send/read/покупки/возвраты/публикации не выполняются.

Не включать одновременно Gifts и склад для одного лота/заказа. Не включать TG_GIFT_REFUNDS_ENABLED, Auto-SENT, глобальное продвижение или автопринятие условий «заодно». PLAYEROK_WRITES_ENABLED само по себе не является разрешением на платежи; нужны действующие отдельные opt-in и лимиты. Перед writes остановить/разобрать посторонние ожидающие операции; никакая чужая PENDING задача не должна случайно попасть в тест.

Для согласованного теста: подтвердить привязку аккаунта/поле получения/актуальную цену и баланс/ровно одну единицу, включить только необходимые разрешения, проверить одно PAID-событие. Наблюдать очередной статус → подтверждённый результат в текущем экране/исходном уведомлении и серверное сообщение/receipt. Для Gift проверить пустую подпись и уникальную независимую квитанцию, а для пакета — каждую позицию. Не считать постановку в очередь, отправку запроса или SENT подтверждением получения покупателем.

Если отправка UNKNOWN/UNCERTAIN — остановить новые действия, не покупать повторно и не возвращать деньги автоматически. Сохранить квитанции. Продолжать только после достоверной сверки. При завершении выключить согласованные тестовые разрешения вручную и проверить отсутствие новых ожидающих действий.

## Осталось подтвердить живьём

Настоящие Telegram edit/media ограничения и задержки через вашу сеть; уведомление с настоящим callback; фактические reply/read receipts Playerok; обновление характеристик настоящего лота; реальная MTProto receipt/delivery при отдельно разрешённой покупке. Offline tests не доказывают эти live-операции.
