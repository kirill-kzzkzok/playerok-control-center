# localVPN: перебор доступных серверов

Установленная служба Playerok использует каталог разрешённых localVPN-серверов.
Бот не копирует их пароли и не создаёт отдельный список по адресам со скриншота.
Доступность порта SOCKS сама по себе не подтверждает работоспособность Telegram.

Исправление нативной службы:

- Убрано ограничение тремя кандидатами: проверяются все разрешённые кандидаты
  в пределах существующего 85-секундного бюджета команды.
- При исчерпании бюджета следующий цикл начинает с оставшихся кандидатов.
- Сохранены проверка владельца SOCKS-порта, актуальность каталога, исключение
  удалённых серверов, TLS/Telegram-проверки и смена поколения маршрута.
- Сохранены STOP и ограничение тремя циклами восстановления с задержкой.
  Если все циклы неуспешны, служба остаётся недоступной; бесконечных попыток нет.
- Переключение маршрута не повторяет бизнес-операции. Подготовленная оплата
  требует того же поколения маршрута; неизвестный результат остаётся в карантине.

Служба собирается из отдельного проекта:
`C:/Users/user/Documents/Codex/2026-10-19/pa/outputs/native-host`.
Воспроизводимое изменение двух Go-файлов сохранено в
`tools/patches/localvpn-five-candidates.patch` (применять из каталога native-host).
Для исходников с Windows CRLF используйте `git apply --ignore-space-change`
с путём к этому патчу; затем выполните `gofmt` изменённых Go-файлов.
Это патч существующей службы, а не второй прокси-движок.

Проверены восемь `TestPlayerok*` на изолированных каталогах и поддельных границах
запуска/проверки порта, включая пятый успешный кандидат, исчерпание бюджета,
изменение/удаление сервера, занятый порт и STOP. `go vet ./...` и сборка прошли.
Живые платёжные операции и реальные переключения серверов не запускались.

На этом компьютере новый бинарный файл атомарно установлен по прежнему пути
`outputs/playerok-proxy/localvpn-playerok.exe`; старый сохранён рядом с суффиксом
`.before-five-*`. Проверен SHA-256 установленной сборки:
`837e86fbe926b6bdb4a68c73dc30e54b8af9658cba8856611d206e2f9f75f407`.
Служба автоматически этой разработкой не запускалась. Новый файл используется
при следующем обычном запуске бота по этому пути. `.env`, сессии, базы и каталог
серверов не менялись. В Git сохраняется исходный патч, локальный exe не публикуется.

В Python бесплатная проверка теперь сообщает понятную причину
`PROXY_UNAVAILABLE` вместо необработанного RuntimeError. Сам сетевой сбой
классификацией исключения не устраняется. Ошибка ACK означает, что Telegram
не подтвердил нажатие; она не даёт разрешения повторить покупку или сообщение.
