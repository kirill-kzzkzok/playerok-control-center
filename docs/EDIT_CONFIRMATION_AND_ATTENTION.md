# Подтверждение правок и закрытые ошибки

Обычная правка объявления отправляется через существующий Outbox ровно один раз.
Если ответ записи не содержит всех ожидаемых полей, бот читает объявление до
четырёх раз с интервалами 0 / 0,2 / 0,8 / 2 секунды. Это интервалы ожидания,
а не гарантия времени ответа API. Ограничение RetryAfter прекращает этот цикл.
Проверяются ID, владелец, все изменённые поля и сохранённые критические параметры.
Lease и аккаунт должны оставаться действующими; другой исполнитель не получает
право завершить операцию по устаревшему ответу.

При несовпадении сохраняется неизвестный результат. В карточке операции и
уведомлении показаны названия неподтверждённых полей, без их значений. Отсутствие
поля в ответе не считается доказанным отсутствием изменения. Повторного запроса
записи нет. Потерянный ответ записи и старые операции без достаточной квитанции
не становятся успешными только потому, что поля сейчас совпадают.

После явного закрытия владельцем **обычной правки объявления** она хранится в
истории с причиной и неизвестным внешним исходом, но не создаёт пункт «Действия
не выполнены» на главном экране. Это не отмена изменений и не подтверждение
успеха. Ограничения привязки и проверки готовности действуют независимо.
После свежей проверки совпадения текущего товара с подтверждённой привязкой
закрытая обычная правка не является активной блокировкой выдачи. Без полного
объявления нужна актуальная проверка; изменённая или неподтверждённая привязка
остаётся заблокированной. Самостоятельно выключенная выдача не включается.

Неопределённые выдачи, платежи, миграции кодов и подтверждения привязок этим
исключением не скрываются. Оплаченные проблемные заказы, карантин склада и
неизвестные подарочные операции остаются в разделе внимания. Закрытие не
освобождает резерв, не отправляет подарок и не повторяет платёж.

Изолированное воспроизведение подтвердило короткое окно проверки как один из
возможных источников ложного отрицательного результата. Причина конкретной
операции владельца без её сохранённых технических доказательств не установлена.
Рабочие базы и реальные объявления при проверке не использовались.

Если карточка товара требует решения, над общей проверкой показывается действие
для первой указанной причины. Для неизвестной обычной операции это
«🔎 Сверить без повторной отправки» → конкретная операция →
«🔍 Проверить результат на Playerok». Для неизвестной покупки/возврата подарка
открывается существующий экран решения именно этого подарочного заказа, где
доступна сверка Telegram или возврата. Открытие экрана не выполняет сверку или
повторную отправку само по себе. Если доказательства не найдены, результат
остаётся неизвестным; сообщение об этом не является успешной доставкой.
