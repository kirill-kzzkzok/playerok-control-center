# Переработка магазина: единый контракт приёмки

Источник — задание владельца от 04.11.2026 после ce4b749, включая восемь
дополнительных требований. Этот документ имеет приоритет над прежним требованием
ручного подтверждения обычного переименования. Остальные финансовые разрешения
и явные STOP не отменены. Работать без субагентов, последовательно, без согласований
между этапами. Не использовать рабочие данные в тестах и не выполнять live-мутации.

## Порядок

1. Полная инвентаризация production, зависимостей, всех UI/настроек/состояний,
   существующих тестов и дефектов: причина → исправление → RED/GREEN → приёмка.
   Статическая карта не является доказательством исполнения кнопок.
2. Устранение необоснованных остановок, автоматическое принятие безопасного названия.
3. Каноническое управление выдачей через существующие сервисы, согласование проекций.
4. Создание/подготовка/публикация/включение одним итоговым действием.
5. Измерение и улучшение ACK, FSM, навигации, транзакций, сети, конкуренции с workers.
6. Все пользовательские экраны и навигация, не только главное меню.
7. Продвижение, глобальные настройки, сообщения и уведомления.
8. Безопасные совместимые перенаправления старых callback, удаление мёртвых дублей.
9. Сквозные/нагрузочные тесты, повторный полный UI-аудит, финальная матрица и CI.

Каждый дефект: воспроизводимый RED до runtime-правки, минимальный GREEN,
соседние реальные Dispatcher/FSM и worker-пути. Согласованные коммиты; PROGRESS
с фактическими exit codes, ограничениями и точкой продолжения после прерывания.

| STATE | Канонический источник каждого параметра и единый согласованный UI/worker-контракт. Намерение владельца, пауза, экстренный STOP, техническая готовность и право исполнения разделены. Нет конкурирующих политик и самопроизвольных изменений при открытии. Число независимых переключателей/состояний уменьшается. |

Лимит на заказ применяется к каждому новому заказу, суточный лимит отдельно. Новый подтверждённый лот/заказ после штатного перевыставления получает собственный расходный предел. Никаких повторных покупок/резервов/выдач. |
| STOCK | Загрузка данных, атомарный резерв одной единицы одному заказу, остатки/сообщения/доставка без отдельного запуска после публикации. Два заказа на последнюю единицу не получают её дважды. |
| TEXT | Введённый постоянный текст автоматически готов к выдаче после подтверждённой оплаты и успешного запуска. |
| PLATFORM | Playerok выдаёт товар, бот не дублирует. Сопровождающие сообщения и допустимая отметка выполнения независимы и опираются на подтверждённый статус. |

Цена RUB не меняет пакет Stars. Отсутствующее поле сокращённого ответа не считается изменением; требуется дополнительное чтение. Опасные изменения блокируются. |
| RECOVER | Фоновое восстановление подключений/товаров/каталога/Stars/оплаченных заказов, безопасная сверка результатов и restart без ручного повторного включения. Никаких декоративных Исправить всё или обязательных Проверить/Обновить. Явный STOP не снимается восстановлением. Неопределённая мутация не повторяется без строгого доказательства отсутствия начала. |
| CALLBACK | ACK p95 <0.5s, локальная навигация p95 <1s, карточка p95 <2s при исправной контролируемой сети. Долгая операция сразу показывает начало, затем результат. Измерить p50/p95 до/после, количество запросов, lock wait, SQLite и UI/worker-конкуренцию. Ограниченные cache/single-flight только для UI, не финансовой авторизации. |
| NAV | Все кнопки проверены через Dispatcher/FSM: действие, результат, контекст исходного сообщения, возврат, отсутствие дублей, restart/старые callback, timeout/RetryAfter/плохой прокси/медленный ACK/параллельность. Не держать общий UI lock на длительных чтениях, когда безопасно разделить. |
| VPN | Проверить реальную нативную интеграцию localVPN, установленный executable/протокол/восстановление, не только patch-файл. Не выдавать offline-ответы за live-сетевую приёмку. |
| SETTINGS | Один краткий раздел глобальных настроек и defaults новых товаров; параметры товара только в его карточке. Технические интервалы/политики/журналы вне основного UX. |
| PROMOTE | Только вкл/выкл, понятный предел расходов, результат и затраты; автоматический выбор допустимого действия в рамках подтверждённого API. Без расписаний/ночных интервалов/дублирующих бюджетов в основном UX. Не смешивать STOP продвижения и выдачи. Нет тарифа/разрешения/бюджета — нет платной очереди; отсутствие бюджета не безлимит. |
| MESSAGES | Один диалог Playerok (не username) — одна карточка с последним временем и хронологией, Ответить/Закрыть. Подтверждённая отправка или честная неизвестность без повторов. Безопасно удалять только обработанный служебный ввод владельца, сохранять переписку/важные квитанции. |
| NOTICES | Группировать повторы; не уведомлять о каждой временной ошибке/проверке/восстановлении. Продажи, сообщения, реальные ручные проблемы и неизвестные деньги не теряются. |

## Границы

Не делать live-покупки, публикации, подарки, ответы покупателям, возвраты и иные
внешние мутации без отдельного разрешения. Последняя просьба о двух лотах
разрешает подготовку/проверку через штатные механизмы, но не реальные тестовые
продажи или обход отключённых разрешений. Никаких fake/stub в production.
Ни один успех офлайн не является доказательством автономной live-эксплуатации.
