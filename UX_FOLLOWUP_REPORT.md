## Границы доказательства

`tests/test_ux_followup.py` использует production Dispatcher/FSM/panels, временную SQLite и контролируемые транспорты. Журнал содержит 25 проверенных путей и 52 фактически выполненных callback instances (включая разные Back nonce). Это **не 52 разных функции и не процент покрытия всего бота**. В этих путях встретились ещё 133 callback instances, которые данный тест не исполнял: они явно перечислены, а не объявлены рабочими по одному префиксу.

Существующий полный pytest продолжает проверять склад, Outbox, Gifts, бюджетные guard, соглашения, подтверждения и неизвестные исходы. Прохождение набора тестов не объявляется exhaustive-проверкой всех динамических состояний 416 прежних деклараций кнопок.

Исходники: navigation.py, router.py, statistics.py/statistics_panel.py, promotions_panel.py, listings_panel.py, item_category_picker.py; тесты — test_ux_followup.py. Независимый reviewer воспроизвёл устаревший recovery capability и преждевременный home commit при повторном timeout; оба случая исправлены и повторно проверены. Дополнительный найденный дефект вложенных тарифов (сохранённый ID вместо объекта для preview) устранён без изменения ID, передаваемого в существующий guarded evaluator.

## Безопасность и ограничения

- Совпадение названия/категории создаёт предложение, а не автоматическое слияние: разные продукты могут совпадать по этим полям. Нужен один осмысленный ответ владельца.
- Неизвестный исход edit/send не превращается в доказательство видимости экрана. Неизвестный платёж не превращается в повтор.
- /start не повторяет операцию магазина. Кнопка восстановления привязана к владельцу, nonce и подтверждённому сообщению либо точной ожидаемой клавиатуре Telegram. После нормального отображения recovery capability сбрасывается.
- При отсутствии известного ID Bot API не позволяет найти неизвестное отправленное сообщение. Объясняющая recovery-панель — отдельный ответ на явный /start; неизвестный старый ID не угадывается и не удаляется. Старые денежные callbacks не получают нового разрешения.
- Расписание/лимиты/участие и разрешение реальных расходов остаются разными существующими проверками. UI не включает платные флаги и не меняет .env.
- Все проверки этого этапа — offline/mock; реальных покупок, Playerok-изменений, возвратов и сообщений покупателям нет. Галерея data/ux-followup-gallery/index.html — production renderers с безопасными фикстурами, не live Telegram.

## Проверить в Telegram

1. /start → Ещё → Статистика → Лучшие товары: при подходящих данных появится «Объединить … (3)», без ввода номеров.
2. При потере панели отправить /start и нажать «Восстановить меню». /panel_reset остаётся совместимым служебным вариантом.
3. Ещё → Автопродвижение → Товары для продвижения → товар → Расписание этого товара. Обычный экран содержит один выбор участия; тарифные проверки и наследование — в дополнительных параметрах.
4. Не подтверждать расходы при проверке UX.

Точные итоговые результаты pytest/CI и checkpoints: PROGRESS.md. Статический UX_BUTTON_MAP.md и функциональный UX_DISPATCHER_JOURNEYS.json имеют разные назначения.

## Дополнительная проверка восстановления медиа

Воспроизведён editMessageMedia, применённый Telegram с потерянным ответом: сохранённый старый экран был текстовым, фактический стал фотографией. /start теперь предлагает recovery также при неподтверждённом edit. Используется ожидаемый тип; другой идемпотентный edit допускается только после однозначного отказа типа, не после timeout. Это проверено отдельным Dispatcher fault-injection тестом. Если Telegram не позволяет установить итог отправки, автоматической повторной отправки панели по-прежнему нет.
