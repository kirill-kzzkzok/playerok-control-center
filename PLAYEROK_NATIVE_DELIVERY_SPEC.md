Добавь в существующий проект Playerok Control Center новый режим автоматизации для товаров, которые уже выдаются самой площадкой Playerok.

Работай с текущим кодом репозитория, начиная с актуального HEAD после 654152b. Сначала изучи существующие механизмы заказов, Outbox, delivery policies, LogicalProducts, auto replies, fulfillment, Telegram UI и обработку событий PAID.

НЕ переписывай существующую систему автовыдачи. Реализуй новую функцию минимальными изменениями, повторно используя существующие сервисы и защитные механизмы.

ЦЕЛЬ

У меня есть уже опубликованные товары, например Call of Duty: Modern Warfare 4 за 90 ₽.

Сам товар и необходимые данные для покупателя уже загружены непосредственно в Playerok. Площадка самостоятельно выполняет встроенную автовыдачу.

Мне НЕ нужно, чтобы бот выдавал товар повторно.

Я хочу один раз включить для такого товара две функции:

1. Автоответ покупателю после оплаты.
2. Автоматическая отметка выполнения заказа со стороны продавца.

После настройки бот самостоятельно обрабатывает будущие покупки без дополнительных ручных действий, если операция поддерживается API и правилами площадки.

1. ИНТЕРФЕЙС

Не добавляй новые кнопки в основную карточку товара.

Используй существующий путь:

Мой магазин → Товары → Выбрать товар → ⚡ Настроить выдачу.

Добавь туда новый понятный вариант:

📦 Выдаёт Playerok

Описание режима:

«Товар уже выдаётся самой площадкой. Бот не отправляет его повторно, а может автоматически ответить покупателю и отметить выполнение заказа».

После выбора режима покажи компактную настройку:

📦 Выдача: Playerok

💬 Автоответ после оплаты: Вкл / Выкл
✏️ Изменить текст ответа

✅ Автовыполнение заказа: Вкл / Выкл

💾 Сохранить

Два переключателя независимы: можно включить только автоответ, только автовыполнение либо обе функции.

По умолчанию оба выключены.

Для автоответа предложи стандартный редактируемый текст:

«Спасибо за покупку! ❤️ Товар выдан автоматически. Приятной игры! Если возникнут вопросы — напишите мне».

Текст хранится отдельно для каждого товара. Не вставляй в сообщение логины, пароли или другие секреты из заказа.

После сохранения в основной карточке товара показывай:

Выдача: 📦 Playerok
Автоответ: 🟢 Включён
Автовыполнение: 🟢 Включено

Если какой-то переключатель выключен, отображай это.

Не показывай технические термины Outbox, FSM, logical_products и прочее в обычном интерфейсе.

2. ПОДДЕРЖКА СУЩЕСТВУЮЩИХ ТОВАРОВ

Режим должен работать с уже опубликованными объявлениями.

Не требуй:
- создания нового объявления;
- повторной загрузки товара;
- заполнения локального склада;
- создания постоянного текста выдачи;
- покупки Telegram-подарков;
- повторной публикации;
- изменения описания;
- добавления #кода, если он не нужен этому режиму.

Не изменяй встроенную выдачу Playerok.

Не создавай второй механизм передачи товара покупателю.

Если для безопасной привязки настроек необходима локальная запись, создай её без изменения публичного объявления и без нарушения существующих LogicalProducts.

3. АВТООТВЕТ ПОСЛЕ ОПЛАТЫ

При обнаружении нового оплаченного заказа для товара с включённым автоответом:

1. Определи точный order_id, item_id и chat_id.
2. Подтверди, что заказ принадлежит моему магазину и имеет допустимый оплаченный статус.
3. Найди сохранённую настройку именно этого товара.
4. Отправь подготовленный ответ покупателю в соответствующий чат.
5. Сохрани подтверждённый результат отправки.

Отвечай на событие покупки, а не на ключевое слово в сообщении покупателя.

Не используй существующие автоответы на входящие фразы как замену новой функции. Можно повторно использовать их безопасный транспорт отправки сообщений.

Каждому заказу соответствует не более одного успешного автоматического ответа.

Повторные WebSocket-события, синхронизация, рестарты или повторные клики не должны создавать дубликаты.

Если сообщение уже отправлено, не отправляй снова.

Если результат отправки неизвестен, не повторяй вслепую: используй существующие механизмы UNCERTAIN и сверки.

При недоступности чата корректно отображай причину.

4. АВТОВЫПОЛНЕНИЕ ЗАКАЗА

Мне нужен автоматический переход заказа в состояние выполнения продавцом, если Playerok предоставляет для этого допустимую API-операцию.

Изучи существующий Fulfillment, обработку SENT и API Playerok.

Не путай:
- оплату заказа;
- выдачу товара площадкой;
- отметку продавца о выполнении;
- подтверждение получения покупателем.

Я считаю встроенную выдачу Playerok гарантированной и не хочу дополнительных проверок содержимого товара.

Не проверяй логин, пароль, содержимое выданного аккаунта или другие данные встроенной выдачи.

Однако сохрани техническую проверку точного ID заказа, принадлежности аккаунту, оплаченного статуса и отсутствия уже выполненной операции.

Если Playerok уже выставил SENT или более поздний статус, не отправляй повторную отметку.

Если для такого заказа доступна операция отметки выполнения продавцом, выполняй её автоматически при заранее включённой настройке и после необходимых проверок.

Используй существующий Outbox, идемпотентность, блокировки, подтверждение результата и защиту от повторных мутаций.

Не подтверждай получение за покупателя.

Не подделывай отчёты, подтверждения передачи или обязательные сведения.

Если конкретная категория либо роль продавца требует личного подтверждения или обязательного отчёта, который нельзя корректно сформировать автоматически, не обходи это требование. Обозначь заказ как требующий моего действия и покажи понятную причину.

Не заявляй, что автовыполнение поддерживается, пока это не подтверждено кодом и контрактом API.

5. ПОРЯДОК ИСПОЛНЕНИЯ

Желаемый сценарий:

Покупатель оплачивает товар → Playerok выдаёт его самостоятельно → бот отправляет сообщение → бот отмечает выполнение продавцом, если необходимо и разрешено.

Для автоответа и автовыполнения должны быть независимые подтверждения результатов.

Если автоответ не отправился, не теряй информацию о заказе.

Если выполнение невозможно, не называй заказ выполненным.

Если заказ уже SENT до обнаружения ботом, не пытайся снова выполнить его. При этом автоответ для нового заказа всё равно может быть отправлен, если включён и ещё не отправлялся.

Если заказ отменён, не запускай новые действия по нему.

Никаких повторных отправок самого товара.

6. НАСЛЕДОВАНИЕ ПОСЛЕ ШТАТНОГО ПЕРЕВЫСТАВЛЕНИЯ

Playerok самостоятельно перевыставляет товары.

Не создавай и не публикуй копии объявлений.

Если для товара уже настроена и достоверно подтверждена постоянная логическая привязка с разрешённым наследованием, настройки автоответа и автовыполнения должны переходить на новый item_id при безопасном наследовании.

Не наследуй настройки по одному только похожему названию.

Если связь нового объявления нельзя подтвердить, останови автоматизацию для этого ID и покажи причину.

7. БЕЗОПАСНОСТЬ И СОВМЕСТИМОСТЬ

Сохрани работу:
- Telegram Gifts;
- уникального склада;
- постоянного текста;
- ручной выдачи;
- текущих автоответов;
- заказов и истории;
- финансов;
- PREMIUM;
- единой остановки;
- существующих механизмов повторной сверки.

Не создавай конфликтующих способов управления одной функцией.

Глобальная остановка автоматизации должна останавливать новые действия нового режима.

Восстановление глобальных разрешений не должно автоматически включать ранее остановленные настройки товара.

Существующие заказы не должны задним числом получать автоматические действия только потому, что я включил режим сейчас.

Сохрани явное согласие на включение будущих автоматических действий.

Не выполняй реальные отправки сообщений, отметки выполнения, публикации или платные операции при разработке и тестировании.

8. ТЕСТИРОВАНИЕ

Добавь профильные тесты, включая:

- новый опубликованный товар с выдачей Playerok;
- два независимых переключателя;
- автоматический ответ после PAID;
- выполнение продавцом, если API это разрешает;
- заказ уже SENT;
- покупатель подтвердил получение;
- два разных товара с разными сообщениями;
- десять одновременных покупателей;
- повторные PAID-события;
- рестарт между оплатой и отправкой;
- неизвестный результат ответа;
- неизвестный результат выполнения;
- остановку автоматики;
- отменённый заказ;
- смену аккаунта;
- штатное перевыставление с новым item_id;
- отсутствие повторной выдачи данных.

Сначала выполни профильные тесты. После завершения запускай общий набор один раз и стандартные проверки Ruff, compileall и selfcheck.

Не опрашивай GitHub Actions в цикле и не трать время на ожидание CI.

9. КРИТЕРИИ ГОТОВНОСТИ

После реализации я должен иметь возможность:

1. Открыть уже опубликованный товар.
2. Нажать «Настроить выдачу».
3. Выбрать «Выдаёт Playerok».
4. Включить автоответ и автовыполнение.
5. Указать текст сообщения.
6. Сохранить настройку.

После этого будущая оплата должна запускать соответствующие разрешённые действия автоматически.

При этом бот никогда не выдаёт сам уже загруженный на Playerok товар.
