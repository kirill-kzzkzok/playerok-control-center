# Playerok Control Center

Локальная Telegram-панель магазина на Python 3.12 / aiogram 3.
Проект в разработке: полный набор критериев PROJECT_SPEC.md пока не принят.
Не включайте автоматическую выдачу или денежные действия, опираясь только на зелёные unit-тесты.

## Установка и запуск на Windows

1. Установить Python 3.12 и запустить `install.bat`.
2. Заполнить локальный `.env` по `.env.example`. В текущей рабочей папке секреты уже перенесены из приватной спецификации.
3. Запустить `start.bat` или `.venv\Scripts\python.exe -m app`.
4. Открыть бота и отправить `/start`. По прямому указанию владельца в текущем `.env` включён `FIRST_START_CLAIM=true`: первый `/start` **в личном чате** атомарно закрепляет владельца в БД. После этого остальные пользователи не получают доступ. Для новых установок безопасное значение шаблона — `false`; предпочтителен явный `OWNER_IDS`.

Для работы через предоставленный Worker: `TELEGRAM_USE_PROXY=true`.
`TELEGRAM_API_PROXY_URL` должен указывать HTTPS-базу Telegram Bot API без `/botTOKEN`.
GET/POST `getMe` и корректный отказ неверному токену проверены отдельно.
Работа polling и передачи файлов должна проверяться независимо от `getMe`.

Проверка подключений: `.venv\Scripts\python.exe -m app.diagnostics`.
Тесты: `.venv\Scripts\python.exe -m pytest -q`.
Статическая проверка: `.venv\Scripts\python.exe -m ruff check app tests`.

## Возможности текущей реализации

- Inline-меню, проверка владельца на message/callback, HTML-экранирование.
- Реальные профиль, товары, категории, способы получения, схема полей и сообщения через PlayerokAPI.
- Мастер локального черновика: выбор игры, категории, полей, описание, фотографии, цена, параметры выдачи, превью; FSM переживает перезапуск.
- Серверные операции создания, редактирования, удаления, бесплатной публикации и ответа через сохраняемую очередь. В штатном `.env` записи выключены. Mock-тесты не доказывают работу этих операций на реальном сервере.
- SQLite WAL, транзакции, уникальные ключи операций, leasing, UNCERTAIN, атомарный запас и резервирование.
- API-сверка истории с пагинацией, уведомления с дедупликацией и сохранением неизвестного результата отправки.
- Decimal-калькулятор с происхождением ставок, отдельными расходами; графики по локальной истории, карточка профиля с реальным рейтингом.
- Продвижение: расчёт cooldown, повторной проверки позиции и лимитов в dry-run. Реального списания модуль не выполняет.

## Ограничения, которые ещё предстоит закрыть

Полная приёмка мастера на Telegram, загрузка фотографий на Playerok, создание/редактирование/публикация тестового лота, установка реальной скидки, точные комиссии вывода, фильтры всех разделов, настройка реальной автоматизации и сверка успешности всех типов UNCERTAIN ещё не подтверждены/не завершены. Замена фотографий существующего лота реализована с повторной проверкой актуальных ID и подтверждением, проверена на mock API; live-записи в рабочие товары не выполнялись.
Контролируемый технический черновик был отклонён Playerok по правилам товара; обход этого ограничения не выполняется. Поиск по уникальному имени не нашёл созданного объекта. Бесплатная публикация не проверялась.
Автоподтверждение нельзя путать с SENT продавца. Автовывод и платные операции запрещены.

Для будущего включения обычных записей существует `PLAYEROK_WRITES_ENABLED=true`; это не разрешает оплату PREMIUM или поднятий. До завершения live-приёмки оставляйте `false`.

Условия категории и инструкции продавцу показываются полностью, постранично. Принятие соглашений — отдельное действие с явным подтверждением владельца и сохраняемой очередью; оно не создаёт товар и не покупает продвижение. При выключенных записях соглашения на сервере не принимаются. Изменившиеся условия нужно прочитать повторно.

Атрибуты и приватные данные существующего товара редактируются через отдельный сохраняемый мастер: перед отправкой проверяются владелец, разрешение редактирования и исходный снимок полей. Параллельные изменения блокируются; приватные значения не выводятся в публичном превью.

Механизм настоящей скидки подтверждён публичным кодом редактора: цена продажи `price` меняется относительно имеющейся `rawPrice`; обычный продавец не задаёт произвольную старую цену. Есть отдельное превью/подтверждение скидки и её снятия, с проверкой минимум 5% и актуальных цен. Реальная запись скидки не выполнялась; проверка пока изолированная. Для нового товара скидка доступна после создания серверного черновика.

Мастер поддерживает постраничные варианты и множественный выбор, предпросмотр/замену/удаление отдельного фото, а для категорий без ITEM_DATA — приватные данные покупателю в поле `comment`. Название и описание проверяются по текущим ограничениям официальной формы (10–72 и 10–2048 символов); стандартная цена — 90–100000 ₽, для подтверждённой роли OFFICIAL_SELLER — от 10 ₽. Это проверка формы, а не гарантия принятия товара сервером.

Очистка `data/uploads` выполняется ежечасно: сохраняются файлы активных черновиков, FSM и незавершённых/UNCERTAIN операций. Успешно обработанные загрузки и старые бесхозные файлы удаляются; при повреждении списка ссылок очистка прекращается с диагностикой.

## Данные и эксплуатация

- Конфигурация: `.env` (приватная, вне Git).
- Приватная спецификация: `PROJECT_SPEC.md` (вне Git).
- База: `data/control_center.sqlite3`; содержит сообщения и данные запаса, хранить как секрет.
- Загрузки: `data/uploads/`.
- Резервные копии: `data/backups/` — SQLite backup API на запуске и по кнопке настроек.
- Логи с ротацией: `logs/control_center.log`.
- Локальные свидетельства live-проверок: `data/live_*.json`, `data/controlled_live_test.json`.

Остановка — Ctrl+C. Два экземпляра для одной БД блокируются OS-lock.
При неизвестном результате внешнего запроса операция получает UNCERTAIN и автоматически не повторяется. Сначала сверяйте реальное состояние сервера.

Восстановление вручную: остановить бот, сохранить текущую БД и её `-wal`/`-shm`, выбрать проверенную резервную копию и заменить файл основной БД при полностью остановленном процессе. Не восстанавливайте старый запас поверх новых выдач без сверки: это может повторно сделать выданные коды доступными. Автоматическое восстановление поверх рабочих данных не выполняется.

Для круглосуточной работы компьютер должен оставаться включённым с интернетом. Автозапуск можно настроить в Планировщике Windows с рабочей папкой проекта; бот не работает при выключенном компьютере.

Прогресс: `PROGRESS.md`; архитектура: `ARCHITECTURE.md`; исследование: `PLAYEROK_RESEARCH.md`; доказательства проверок: `TEST_REPORT.md`.
Переиспользованный PlayerokAPI распространяется по MIT; сохранён `LICENSE.PlayerokAPI`.


## Финансовый калькулятор

В настройках откройте «Условия вывода», выберите доступный метод и введите предполагаемую
сумму. Это калькулятор: реквизиты не запрашиваются, деньги не выводятся. Выбранный метод
сохранится для вашего Telegram ID и подставится в новые черновики. Условия можно обновить;
старый курс/тариф не считается актуальным.

В превью черновика кнопка «Вывод и себестоимость» позволяет выбрать метод для этого
товара и ввести стоимость одной единицы. Отдельная финансовая карточка есть у существующих
товаров. Для серверного черновика можно включить стоимость будущего размещения, включая
PREMIUM, полученную из API. Это только preview: платное действие не выполняется.

Комиссии продажи/вывода, размещение и себестоимость разделены. Прибыль появляется только
при наличии всех нужных составляющих и себестоимости; иначе показываются известные суммы
и причины, почему итог недоступен. Вывод суммы одной продажи может быть ниже минимального
лимита — в таком случае бот не обещает поступление. Минимальная комиссия при объединённом
выводе нескольких продаж распределяется иначе.

USDT включает доплату 1 USDT по полученному курсу; результат показан в рублёвом эквиваленте.
Фактическое округление settlement ещё не проверено, поэтому расчёты явно помечены оценками.
Время источников показывается по Москве. История оценок хранится в financial_quotes,
отдельно от подтверждённых расходов/поступлений. Это не история реальных выводов.


## Сверка и история сообщений

В диалоге доступны страницы «Старее/Новее»; открытие истории не отмечает её прочитанной.
Кнопка «Прочитано» показывает подтверждение и требует разрешённых записей Playerok.
В штатном read-only режиме записи заблокированы. Вложенные фото открываются отдельной
кнопкой; отправка фото требует превью и подтверждения. Live-отправка ещё не проверена.

Сверка загружает историю частями, сохраняет курсоры и продолжает после перезапуска.
BACKFILL означает продолжающуюся первую загрузку; ERROR — ошибку одного или нескольких
потоков. Один цикл ручной сверки не означает, что вся история уже загружена. Большое
число диалогов увеличивает задержку обнаружения. WebSocket ускоряет сверку, но не заменяет её.


Быстрые ответы доступны в настройках и при нажатии «Ответить»: можно сохранить
собственные шаблоны, изменить или удалить их. Перед отправкой всегда показывается
полный текст с отдельной кнопкой подтверждения. Введённый вручную текст работает так же.
Шаблоны принадлежат вашему Telegram ID и сохраняются после перезапуска.

Исходные уведомления не заменяются экраном ответа. Для ответа из уведомления бот
сохраняет связь и обновляет его результатом из очереди операций. UNCERTAIN означает,
что результат неизвестен: перед любым повтором нужна проверка на Playerok. При сбое
обновления Telegram повторяется только редактирование уведомления, не сообщение покупателю.
Эти сценарии пока проверены в тестовой среде; live-отправка покупателям не выполнялась.


Фото в диалоге открываются кнопкой «Открыть фотографии». Бот проверяет, что сообщение
ещё доступно, и загружает изображение с ограничением размера. Если страница сдвинулась,
обновите диалог. При открытии прочитанность автоматически не меняется.

Для ответа фото откройте «Ответить» и пришлите одну фотографию или файл JPEG/PNG/WEBP
с необязательной подписью. Бот покажет preview и отдельную кнопку подтверждения.
Альбомы пока не объединяются: одно фото соответствует одному подтверждаемому ответу.
В штатном read-only режиме реальная загрузка/отправка заблокирована. Контракт сверён
с текущим веб-клиентом и покрыт mock-тестами; live-фото покупателям не отправлялись.


## Неопределённые операции

В диагностике откройте «Неопределённые операции» или «История операций». При UNCERTAIN
бот не повторяет отправку автоматически. Для ответа/выдачи можно указать ID сообщения
из истории диалога: бот сопоставит отправителя, текст, время и число вложений. Фото
нужно лично сверить на Playerok. Проверка ограничена 480 сообщениями; отсутствие
совпадения не доказывает, что отправки не было. Для прочитанности проверяется текущее
состояние чата. Решение требует комментария и отдельного подтверждения.

Можно остановить операцию без повтора, оставив внешний результат неизвестным. Резерв
сохранится в карантине, фото — для сверки; новых отправок не будет. Ручное подтверждение
выдачи меняет только локальный учёт и не завершает сделку на Playerok. Для прочих типов
операций успешность этим интерфейсом не устанавливается; доступна остановка без повтора.
Ручное решение и исходная ошибка остаются в журнале. Не вводите секреты в комментарии.


WebSocket включён по умолчанию; PLAYEROK_REALTIME_ENABLED=false отключает его,
оставляя периодическую сверку API. В диагностике видны состояние подключения и очередь
адресных сверок. После обрыва бот переподключается с задержкой и перечитывает данные.
Завершённый catchup cycle не означает полной загрузки истории: проверяйте BACKFILL.
В реальной проверке подтверждены handshake и heartbeat; новые события покупателей
не создавались, поэтому полный live-поток событий ещё не принят.


## Заказы и локальный запас

В заказах доступны поиск по ID/товару/покупателю, фильтры, подробная карточка и история.
Локальная проблема и заметка видны только в панели: это не жалоба на Playerok.
При недоступном API карточка использует явно обозначенный кеш; выдача из него отключена.

У оплаченного заказа можно локально добавить уникальные коды по строкам и отдельно
подтвердить выдачу одной единицы. Записи Playerok в штатной конфигурации выключены.
Выдача перед отправкой проверяет актуальную продажу и чат; timeout оставляет карантин.
Код никогда не возвращается в доступный запас автоматически. Добавление кодов само
по себе не отправляет их покупателю и не включает автоматизацию.

Отправленный код не означает отметку SENT или подтверждение покупки. Кнопка «Я выполнил заказ» открывает checklist и, если требуется, форму отчёта.
Состояние сделки и требования проверяются повторно перед записью.
Реальные выдачи и изменения статуса этой контрольной точкой не проверены.


Отметка выполнения требует личного подтверждения передачи товара и отдельного подтверждения.
Для официального продавца могут понадобиться данные исполнителя и поставщика, номер
заказа и стоимость. Это отчёт, не оплата. При недоступном списке поставщиков нельзя
подставить произвольного поставщика. Timeout записи не вызывает автоматического повтора.
В штатном read-only режиме отправка заблокирована. Live-изменение статуса/отправка отчёта
не проверялись: данные ветки пока приняты только в изолированных тестах.


## Политики выдачи

В карточке товара откройте «Политика выдачи · dry-run». Можно сохранить режим,
постоянный текст, приветствие, сообщение после выдачи и запрос отметки SENT.
Переключатель задаёт желаемое включение; автоматическое исполнение пока выключено,
что явно показано на экране. Сохранение настройки не отправляет сообщения и не меняет лот.

После сохранения можно выбрать локально известный оплаченный заказ для dry-run: бот
перечитает его и чат через API, покажет причины запрета и предполагаемые шаги. Код
не резервируется, отправки не создаются. «Выключить все политики выдачи» доступно
в общем разделе автоматики; ранее подтверждённые ручные операции проверяйте отдельно.


Цепочки приветствие → выдача → сообщение после выдачи можно зарегистрировать для
отдельного заказа после dry-run и подтверждения. Для исполнения нужны оба локальных
флага PLAYEROK_WRITES_ENABLED и PLAYEROK_AUTOMATION_ENABLED; штатно они выключены.
Старые оплаченные заказы автоматически не включаются. Следующий шаг отправляется только
после подтверждения предыдущего; неизвестный результат останавливает продолжение.
Изменение политики останавливает её текущие цепочки. Отметка SENT остаётся отдельным
подтверждаемым действием; успешная отправка кода не означает подтверждение покупки.
Цепочки проверены изолированно, live-отправок покупателям не выполнялось.


## Продвижение: настройки и проверка без покупки

Откройте «Автоматизация → Продвижение · dry-run». Доступны интервалы и пороги,
ночное время МСК, cooldown, лимиты расходов и выбор всех подходящих/отдельных лотов.
Конкретный лот можно включить или исключить в его карточке продвижения. Изменения
нужно сохранить; параллельный старый редактор не перезапишет новую версию.

Проверка читает реальную цену размещения, сравнивает интервалы и лимиты. Для режима
позиции нужны два чтения с интервалом; быстрый повтор кнопки недостаточен. Позиция
приоритетного размещения не доказывает общее место товара в поиске. При превышении
лимита политика локально выключается. Dry-run ничего не покупает и не записывает
оценку как расход. Платное исполнение отсутствует; история показывает сохранённые
записи расходов, если они есть. Эти сценарии проверены изолированно, без реальных поднятий.


Планировщик продвижения периодически выполняет только dry-run для включённой политики.
Он сохраняет очередь и курсор каталога, учитывает ошибки и продолжает после перезапуска.
При выключенной политике запросов нет. Для каждого лота проверяется стоимость текущего
класса размещения; неоднозначная цена не означает автоматический выбор PREMIUM.
Состояние видно в диагностике. При выключении политики из-за лимита приходит локальное
уведомление с указанием, что списания не было. Реальные поднятия не выполняются.


В разделе автоматики доступны «Все политики выдачи» и «Цепочки выдачи»; в продвижении —
выбранные/исключённые лоты, очередь проверок, история dry-run и расходов. Списки имеют
страницы. Карточка цепочки содержит операции шагов без показа данных выдачи.

Остановить цепочку можно после отдельного подтверждения. Уже отправленное не отзывается;
запрос в полёте может завершиться и сохранит настоящий результат. Зарезервированный код
остаётся в карантине. Если цепочка изменилась после открытия подтверждения, проверьте
её снова. Неизвестные цепочки автоматически не возобновляются.

В очереди продвижения можно локально запланировать новую dry-run проверку. Это не
покупка и не включение политики; выполняющийся lease не сбрасывается. Исторический
результат dry-run не подтверждает сегодняшние условия или факт списания.


## Автовыдача будущим продажам

В политике товара есть отдельный переключатель «Будущие заказы автоматически».
Он выключен по умолчанию. Для enabled-политики сохранение такого выбора требует
дополнительного подтверждения; реальное исполнение требует также двух глобальных
флагов PLAYEROK_WRITES_ENABLED и PLAYEROK_AUTOMATION_ENABLED. Штатно они выключены.

Автоматически включаются только продажи с подтверждённым серверным временем создания
после сохранения текущей версии политики. Старые, неизвестные по времени и созданные
до новой версии заказы не получают код автоматически. После изменения политики
начинается новый отсчёт. Пропуски и блокировки видны в «Регистрация будущих заказов».
Сетевые ошибки чтения имеют задержку; неопределённые отправки не повторяются.

При окончании запаса новые автоматические регистрации блокируются. После пополнения
проверьте и сохраните включённую политику заново. Отметка SENT остаётся отдельным
подтверждаемым workflow; получение кода не означает buyer confirmation. Весь сценарий
пока проверен изолированно, реальным покупателям тестовые выдачи не выполнялись.

## Профиль и аналитика

Профиль показывает доступный баланс и сумму к выводу раздельно, статистику объявлений,
продаж и покупок из текущего API-ответа. В статистике доступны пять периодов, несколько
графиков, лучшие товары и категории. Временные графики — плавные линии: точки показывают
исходные значения, линия между ними — визуальное сглаживание, не прогноз.

Статусы заказов текущие, период определяется серверной датой создания. Отсутствующие
даты догружаются ограниченными read-only запросами деталей с сохранением очереди.
Счётчики неполноты/покрытия доступны в «Подробности». Выручка до комиссий не является
поступлениями или прибылью. Расходы продвижения и другие расходы показаны отдельно;
финансовая сверка транзакций ещё не принята. Текущая live-сессия 30.10 вернула
UNAUTHORIZED_OR_CHALLENGE; история не объявляется полной до восстановления доступа.

В статистике кнопка «Поступления и расходы по транзакциям» показывает отдельную
историю подтверждённых движений баланса по дате завершения транзакции. Продажи,
пополнения, списания выплат, PREMIUM и прочие приоритеты разделены. Загрузка выполняется
частями и продолжается после перезапуска; ошибки/покрытие видны в панели. Суммы без
серверной даты завершения или в другой валюте не подставляются в рублёвый итог.
Сумма списания выплаты и явное поле API «к получению» показаны отдельно; деньги в банке
этим не подтверждаются. Комиссии с неясными единицами и историческая прибыль не выдумываются.

В карточке заказа кнопка «Себестоимость и прибыль» ведёт в исторический учёт. Себестоимость
всего заказа и остальные расходы вводятся явно (в том числе 0), отдельно от текущих
расчётов товара. Подтверждённый PREMIUM/удержания выплаты можно распределить между заказами:
доли не превысят источник. Для выплаты используется только разница списания и явной суммы
к получению из API. Это не повторное вычитание всей выплаты.

После заполнения проверьте полноту расходов. При одном однозначном подтверждённом SELL-
зачислении бот покажет прибыль по вашему учёту; неизвестные данные блокируют итог. Смена
исходных сумм требует повторной проверки. Не включайте распределённые расходы повторно в
прочие расходы. Раздел статистики показывает результат только по проверенным заказам и
число исключённых; это не заявление о полной прибыли магазина или банковской выписке.
