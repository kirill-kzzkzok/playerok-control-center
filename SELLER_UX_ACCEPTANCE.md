# Упрощение управления Playerok — приёмка 02.11.2026

Исходный контракт: [SELLER_UX_SIMPLIFICATION_SPEC.md](SELLER_UX_SIMPLIFICATION_SPEC.md).
Контрольная база A1: f6531f9. Продолжение выполнено без субагентов.
Это отчёт локальной реализации, а не акт live-приёмки финансовых операций.

## Навигация и сценарии

```text
Мой магазин
├─ Товары (по умолчанию активные)
│  ├─ Создать → описание/фото/цена → выдача → серверный DRAFT
│  │  └─ Сообщения/лимиты/завершение/тариф → проверить → опубликовать и запустить
│  ├─ Поиск: весь доступный каталог, код, статусы, выдача, проблемы
│  └─ Карточка: цена, себестоимость, оценка, статус, выдача, код/наследование
│     ├─ Запустить продажи (для остановленной настроенной выдачи)
│     ├─ Сколько получу чистыми → параметры/подробности
│     ├─ Редактировать → текст / цена / характеристики / отдельные фотографии
│     ├─ Выдача → единая настройка / склад / проверка без отправки
│     ├─ Продвижение → тариф → одно подтверждение разового расхода
│     └─ Другие действия → ссылка / подробности / подтверждаемое удаление
├─ Заказы → карточка → чат / допустимая выдача / завершение / подробности
├─ Сообщения → диалог → ответ → подтверждение → подтверждённый результат
├─ Подарки → товары / история / настройки / видимый экстренный STOP
└─ Ещё → статистика / автоматизация / автопродвижение / профиль / настройки / инструменты
```

Пять постоянных входов сохранены: эта уже существующая структура даёт прямой вход
в сообщения и Gifts; создание занимает два нажатия. Изменение этой структуры на
пример из ТЗ убрало бы эти ежедневные действия с первого экрана. Подмены функций
вторым интерфейсом нет. Старые безопасные маршруты остаются; прежние финансовые
подтверждения отдельной проекции не получают новой силы.

## Конкретные внешние ограничения

- Ни новых реальных Playerok create/edit/publish/PREMIUM, ни Stars, возвратов или
  сообщений покупателям при разработке не выполнялось. Live Windows Telegram UI
  не запускался. Автотесты не доказывают фактическую доставку через реальные API.
- Автоперевыставляет Playerok. Бот проверяет и наследует, но не копирует и не
  перевыставляет сам. Разрешение наследования не доказывает включение функции на сайте.
- Описание не имеет подтверждённого server-side CAS. Проверки до/после записи
  сокращают риск, но внешнюю правку ровно между GET и POST исключить нельзя.
- Каталог не является атомарным серверным снимком: полнота страниц проверяется,
  но внешние изменения во время сканирования могут потребовать нового прохода.
- Перестановка фото не предлагается: поддерживаемый клиент даёт add/remove,
  отдельного подтверждённого reorder API нет. Новое фото может оказаться в конце.
- При потере самого ACK создания без надёжного item ID повтор создания запрещён.
  При сохранённом ID и потерянном readback доступна отдельная безопасная сверка.
- Серверный момент PAID не подтверждён текущим контрактом. Поэтому «от server-paid»
  честно без измерений; created_at заказа не используется вместо момента оплаты.
- Времена нагрузочного теста — локальная симуляция. SLA 15–30/60s на настоящей сети
  не обещается. Повторные чтения оплаты/получателя/цены сохранены как safety fences;
  доказанно безопасного основания убрать их нет.
- UNKNOWN/UNCERTAIN требуют положительной сверки. При её отсутствии ни повторного
  подарка, ни полного возврата после начатой оплаты не будет. Правила площадки,
  требующие отчёт о выполнении, не обходятся.

## Безопасная ручная проверка интерфейса

Перезапустите бот штатным start.bat. Откройте /start → Товары → карточка.
Проверьте поиск по названию/коду, фотографии (не подтверждая запись), финансовый
прогноз и глобальный способ получения денег в профиле. В настройке нового товара
можно выбрать подарки и посмотреть превью без оплаты. Для сохранения настроек,
публикации, покупки PREMIUM или отправки по реальному заказу требуется отдельная
live-приёмка с явным согласием владельца. Никакие флаги .env этим обновлением не включены.
